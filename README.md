# 午托点名 PWA v1.6.3（宇才教育 · 午托点名 + 培训签到）

iPhone 优先的单机网页应用：午托点名和培训签到分成两套独立档案、两套底部导航（模式切换互不干扰）。断网可用，数据只保存在当前浏览器的 IndexedDB 中，不依赖账号或业务服务器。

**v1.6.3 请假不计上课，统计口径统一**：学生标为**请假**时，这节课不再计入学生的「上课次数」（也不算出勤或迟到），只让请假次数 +1；上课次数严格等于 出勤 + 迟到（统计内部另记 `scheduled` 排课总数供核对）。老师统计联动同一口径：**授课人次只累计出勤 + 迟到**；一节课至少有一名学生出勤或迟到才计老师「上课节数」，**整节课全体请假时老师不计这节实际授课**（按日期 / 按科目、平均人数分母、「最近课程」都只用实际授课的课程）。培训概况的「老师上课次数」与老师统计完全一致。签到页顶部原「签到人次」改为**「上课人次」**（= 出勤 + 迟到），出勤、迟到、请假、未归状态仍显示真实数量，当日课程记录数不变（全请假的课照常列出、不隐藏）。请假记录不消失：签到明细、课程卡片和 CSV 导出仍完整保留。状态改判幂等：出勤改请假只减一次上课、加一次请假，改回即恢复，重复写同一状态不重复计数。

**v1.6.2 培训签到时间 30 分钟档位 + 默认 90 分钟**：新增 / 编辑培训签到的开始、结束时间从时间输入框改为**下拉选择**，只能按 `00 / 30` 分钟档位选（开始 `00:00–22:00`，结束最晚 `23:30`，不支持跨日）。新开签到时先选开始时间、结束框禁用；**选定开始时间后结束时间自动设为开始 + 90 分钟**，可手动改，改了开始时间则结束重新回到「新开始 + 90 分钟」；只改结束不会被重置。编辑旧课程保留原有起止时间（历史非档位时间在表单里标为「旧时间」，不改历史数据）；一旦改动时间就必须符合新的档位规则，保存时业务层会再校验一遍。

**v1.6.1 两段式落位动画 + 在线更新**：点名点击后的落位从 200ms 拉长到 320ms，曲线换成前段平缓的 `cubic-bezier(0.22, 0.61, 0.36, 1)`，起手约 10% 时长停在原格并轻微放大 1.035 倍，让眼睛先看清"就是这张"再下落；未点卡片的补位延后 70ms 启动、260ms 走完（`fill: "both"` 把延迟期锁在旧位置），"先落、后补"的主次看得清；落位期间被点卡片层级抬高，不会被补位卡片盖住。Service Worker 的导航请求改为 **network-first**：在线打开 / 刷新优先拿最新页面并写回缓存，断网回退缓存照常点名；页面在"旧控制器被新控制器顶掉"时自动刷新一次（带防循环保护）；培训「概况」页最底部新增小版本标记，用来确认手机拿到的是新版。

**v1.6 手机桌面品牌名与点名重排动画**：添加到主屏幕后的应用名称统一显示「宇才教育」（`manifest` 的 `name` / `short_name` 与 `apple-mobile-web-app-title`），页面内部业务标题仍是「午托点名」；午托点名点击学生后，卡片按真实重排位置播放位移动画——被点的卡片向下进入已点名区域，其后的未点卡片向上补位；开启「减少动态效果」时不做上下位移，只保留极轻微反馈。

**v1.5 新增科目档案**：科目独立建档（名称 / 备注 / 启用状态），一位老师可任教多个科目；签到新建课程必须从科目档案选科目（老师任教科目优先，没配置科目时回退全部启用科目）；课程卡片、明细、统计和 CSV 都显示科目名称；旧版本的科目文本会在升级时自动迁移成科目档案。

**v1.4 新增培训签到与统计**：按“日期 + 起止时间 + 老师 + 多名学生”记录一节课，学生逐个标为 **出勤 / 迟到 / 请假**；支持新增、调课、删除课程，学生统计和老师统计，以及 CSV 导出。

> 重要：这是单机版。部署到云服务器或 GitHub Pages 只是让手机浏览器打开网页，数据不会自动在手机、平板、电脑之间同步。换设备请用 JSON 备份恢复。

## 模式隔离与导航

- 打开应用后顶部有「午托 / 培训」二段模式切换，记住上次位置。
- **午托模式**底部导航：点名 / 名单 / 记录（状态笔、进度条只在这里出现）。
- **培训模式**底部导航：签到 / 档案 / 统计 / 概况。
- 两套模式的学生档案、课程与签到数据完全隔离，互不读写。

## 手机桌面名称与点名重排动画（v1.6 / v1.6.1）

### 桌面名称

- `manifest.webmanifest` 的 `name` 与 `short_name` 都是 **宇才教育**；iOS 的 `apple-mobile-web-app-title` 同样是 **宇才教育**。
- 页面内部业务标题（标题栏与页面内容）仍为「午托点名 / 培训签到」，不受影响。
- 图标继续用本地 `icons/180·192·512`，没有新增品牌图片。
- 已经装到桌面的旧图标要改名字，需要在手机上先删除图标，再重新「添加到主屏幕」（浏览器按安装时的清单缓存名称）。

### 重排动画（v1.6.1 两段式）

- 只在**用户操作导致卡片真实换位**时播放：标记状态、长按改状态、撤销、清除记录。
- **不播**：首次加载、搜索、筛选、切换日期、切换模式、来回切页签。
- 做法是原生 WAAPI + FLIP：重建前用 `offsetLeft / offsetTop` 记录布局（纯布局值，不受正在跑的 transform 干扰），重建后以新布局为终点反向算出位移，从 `translate3d(dx, dy, 0)` 回到 `translate3d(0, 0, 0)`；只用 `transform`，不动 `top/left/margin/尺寸`。
- **被点卡片（落位，`data-motion="drop"`）总时长 320ms**，曲线 `cubic-bezier(0.22, 0.61, 0.36, 1)`（前段平缓，不再几十毫秒走完大半距离）；关键帧为：起手 10% 停在原格 → 轻微放大到 1.035 并下落 → 到达新位置后收回 `scale(1)`。
- **未点卡片（补位，`data-motion="float-up"`）延后 70ms 启动、260ms 走完**，用 `fill: "both"` 把延迟期锁在旧位置——不会先闪到新位置再动画；纯横向移动用 `shift`（240ms）。
- 落位期间被点卡片 `z-index` 抬高并带投影，补位卡片在低层级，主次分明；动画结束立即移除 `data-motion` 与 WAAPI 动画对象，transform 与层级随之复原（动画期间 CSS transform 过渡临时关闭，避免和 WAAPI 抢场）。
- 快速连点不等上一轮结束：每轮按当时真实布局重新算，业务写入不排队、不阻塞。
- 系统开启「减少动态效果」（`prefers-reduced-motion: reduce`）时不做上下位移，卡片瞬间换位，只留 ≤150ms 的透明度反馈。

### 在线页面更新（v1.6.1）

- `sw.js` 版本随应用升级（当前 `wudian-v1.6.2`）；**导航请求 network-first**：在线时先取最新 `index.html` 并写回缓存，网络失败才回退缓存（断网仍能打开、照常点名）；静态资源仍是 cache-first。
- 保留 `skipWaiting` / `clients.claim` 与旧版本缓存清理。
- 页面监听 `controllerchange`：**只有"本来就有旧控制器、被新控制器顶掉"时自动刷新一次**；首次安装只接管不刷新，且有 reloading 标志防循环。
- 培训「概况」页内容最底部有 `#appVerBadge`（`data-app-version`）小版本标记，字号 11px 不抢主内容，用来肉眼确认缓存是否已更新。

## 科目档案与一师多科

1. 培训模式 →「档案」→ 页签切到「科目」，可搜索、只看启用、新增、编辑、启停。
2. 科目表单包含：名称（必填）、备注、启用状态。同名科目（忽略多余空白与大小写）会被拦截。
3. 科目列表显示启用状态和引用计数（被多少位老师、多少节课使用）。
4. **被老师或课程引用的科目不能删除**，界面会提示改用停用；停用后不参与新签到选科，历史课程仍显示当时的科目名称。
5. 老师表单的科目字段改为从科目档案**多选**（勾选），老师行显示多个任教科目（如“数学、奥数”）；停用的历史科目在编辑时仍可见并标明“已停用”。
6. 旧版本老师 / 课程里的科目文本，升级加载时自动迁移成科目档案并补齐关联（幂等，重复打开不会重复建档）。

## 培训签到操作

1. 打开底部「签到」→「新增培训签到」。
2. 选择上课日期、老师；**开始时间按 30 分钟档位下拉选择（00:00–22:00）**，选定后**结束时间自动填开始 + 90 分钟**（可手动改成开始之后、23:30 前的任意 30 分钟档位；改开始时间会重新回到 +90）。
3. **科目为下拉必选**——老师任教了唯一科目时自动预选，多科时自己选；老师没配置科目时列出全部启用科目。
4. 编辑旧课程时，起止时间保留原值（历史非档位时间显示为「旧时间」选项），无科目的历史记录可以保持不选；一旦改动时间，就必须按新的 30 分钟档位选择。
5. 点学生姓名完成多选；再给每名已选学生点「出勤 / 迟到 / 请假」。
6. 全部已选学生都标好状态后才能保存；漏标会提示并阻止提交。
7. 点当天课程卡片可查看明细、当场改状态、修改课程或删除课程。

老师、学生、科目档案都在「档案」页内维护。午托学生不会自动进入培训名单，培训学生也不会出现在午托点名页。

## 培训规则与统计口径

- 签到状态固定为三种：**出勤 / 迟到 / 请假**，没有默认“待点名”状态。
- 同一名学生一天可以上多节课；同一名老师一天可以上多节课；一位老师可以任教多个科目。
- 同一时间段允许多名老师分别开课。
- 同一名学生不能在同一重叠时间段被排进两节课；修改时间、老师或名单时也会重新检查冲突。
- 一节课可以有多名学生，每名学生各自保存一条签到明细。
- 课程保存「科目 ID + 科目名称快照」：科目改名后，历史课程仍显示课程发生时的名称。
- **学生统计 / 老师统计的「按科目」**优先按科目 ID 归并（改名不拆组）；没有科目 ID 的旧课程按科目文本回退归并。
- **学生统计**按学生筛选课程，**上课次数只含出勤、迟到**（v1.6.3 起请假不计上课，只计请假次数）；同时分别统计出勤、迟到、请假、未归状态次数；「最近上课」只列实际到课的课程。
- **老师统计**只统计至少有一名学生的课程，**上课节数只算「至少一名学生出勤或迟到」的实际授课**（整节全请假不计）；授课人次 = 出勤 + 迟到；出勤 / 迟到 / 请假 / 未归仍按区间内全部已排学生逐条累计；按日期、按科目、平均人数分母都只用实际授课课程；「最近课程」只列实际授课的课程。
- 老师上课次数（含概况页）与老师统计同口径，按「实际授课节数」统计，不按学生人数重复计算。
- 排课、调课、请假都在同一处完成：用课程时间记录排课，用“修改课程”调课，用学生状态“请假”记录请假。

## 一、部署（二选一，都要 HTTPS）

### 方式 A：GitHub Pages

1. 新建一个 GitHub 仓库（如 `wudian`），把 `index.html`、`manifest.webmanifest`、`sw.js`、`icons/` 上传到仓库根目录。
2. 仓库 **Settings → Pages**，Source 选 `main` 分支 `/ (root)`，保存。
3. 等 1~2 分钟，访问 `https://<你的用户名>.github.io/wudian/`。

### 方式 B：Cloudflare Pages

1. 登录 [pages.cloudflare.com](https://pages.cloudflare.com) → **Create a project → Direct Upload**。
2. 上传本目录（含 `icons/` 子目录；不需要上传 `tests/`、`tmp/`、`screenshots/`）。
3. 部署后得到 `https://wudian.<你的子域>.pages.dev`。

> 升级部署时，把 `sw.js` 顶部的 `VERSION` 改成新号，确保手机旧缓存被清除。

## 二、iPhone / 安卓添加到主屏幕

1. iPhone 用 Safari，安卓用 Chrome 打开部署地址。
2. iPhone：分享 → **添加到主屏幕**；安卓：菜单 → **添加到主屏幕 / 安装应用**。
3. 桌面图标名称显示为 **宇才教育**（v1.6 起的清单名称），点进去仍是午托点名应用。
4. 首次联网打开一次，之后 Service Worker 会缓存外壳，断网也能打开。
5. 数据存在当前浏览器。清理网站数据、卸载浏览器或换设备前，先导出 JSON 备份。

## 三、备份与恢复

- 记录页 →「数据」→ **全量备份 JSON**：包含午托学生、头像、记录、设置，以及培训老师、培训学生、课程和签到明细。
- 恢复时选择之前的 JSON，确认后覆盖对应数据。旧版不含培训段的备份不会清空现有培训档案。
- 换手机：旧手机导出 JSON → 传到新手机 → 新手机打开应用并恢复。
- 建议每周固定备份一次，重要调课后也可立即备份。

## 五、常见问题

**Q：手机和电脑能同时用同一份数据吗？**

不能自动同步。当前是单机网页版，每台设备各存各的数据。需要多设备实时共享时，必须另做服务器和数据库，属于下一阶段。

**Q：老师和前台都能操作吗？**

可以共用同一台设备上的页面，但当前没有登录和权限区分。不要在没有权限控制的公共设备上保存敏感联系方式。

**Q：断网后打不开或数据没了？**

首次必须联网打开一次以安装 Service Worker。清除网站数据会清掉本地记录，请定期导出 JSON。

**Q：Excel 打开 CSV 中文乱码？**

应用导出的 CSV 带 UTF-8 BOM，Excel 直接打开应正常；若被其他软件另存坏掉，请重新从应用导出。

**Q：学生毕业或老师离岗，删除还是停用？**

建议停用。停用不参与新签到，但历史课程和统计仍保留。删除档案会按现有规则清理关联数据，操作前先备份。

**Q：一个人一天能记几节？**

培训按课程记录，同一学生一天可以有多条签到明细；只要时间段不重叠即可。

## 技术说明

- 数据存储：IndexedDB。午托使用 `students / records / avatars`；培训使用 `trTeachers / trStudents / trSubjects / trCourses / trAttendance`。数据库只做加法升级（v1.4→v1.5 自动新增 `trSubjects` 并迁移旧科目文本；v1.6.2 不动表结构，DB_VER 仍为 3）。
- 培训签到时间（v1.6.2）：开始 / 结束时间为 30 分钟档位下拉（开始 00:00–22:00，结束最晚 23:30，不支持跨日）；选定开始后结束默认 +90 分钟；编辑旧课程保留原时间，历史非档位时间以「旧时间」临时选项兼容显示与保存；业务层 `trSaveSignin` 保存时二次校验档位与先后关系。
- 点名重排动画：原生 WAAPI + FLIP，`renderGridOnly()` 只在用户操作导致重排时接收 `{clickedId}` 参数并播放；落位 320ms / 补位延迟 70ms + 260ms，曲线 `cubic-bezier(0.22, 0.61, 0.36, 1)`，无动画库、无外部资源。`window.__test.motion` 只读暴露各段时长 / 曲线 / 当前标记数，供自测观测。
- 培训科目：老师挂 `subjectIds` 数组（一师多科）；课程保存 `subjectId + subjectName` 名称快照，科目改名不改历史。
- 签到明细主键为 `courseId|studentId`，同一课程内幂等，同一学生一天可跨多节课记录。
- 培训对外 API：`window.Training`，含档案、课程、签到明细、快照恢复等接口。
- 离线：`sw.js` 导航请求 network-first（在线优先拿新页面，失败回退缓存），静态资源 cache-first 预缓存；无 CDN、无第三方统计、无外部图片。
- 隐私：业务数据不出设备；静态页面本身可由任何 HTTPS 静态托管提供。
